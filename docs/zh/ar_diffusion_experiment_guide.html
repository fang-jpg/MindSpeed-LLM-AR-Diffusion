1. 这轮实验只回答什么

Block：B

一次放入多少个待预测位置。本轮测试 4、8、16、32。

去噪步数：S

填完一个 block 最多做几次去噪前向。本轮只测快速、平衡、保守三档。

真实速度

主表仍填单请求等价 tok/s 及其相对 AR 加速比；8 卡总吞吐另存，不能混为算法加速。

模型性能

用相同 5-shot prompt 在完整 GSM8K test（1319 题）上比较答案正确率。

同一 B 下：S 越少通常越快，但一次要确认更多 token，正确率可能更低
Block B快速平衡保守Exp ID
4S=1S=2S=4B04-S01 / S02 / S04
8S=2S=4S=8B08-S02 / S04 / S08
16S=4S=8S=16B16-S04 / S08 / S16
32S=8S=16S=32B32-S08 / S16 / S32
本轮不做：阈值 sweep、SOL sampler、checkpoint 轨迹和重新训练四个 block。这些都不是完成主表所必需的。

2. GSM8K 数据怎么处理

结论 不需要把整个 GSM8K 复制进 MindSpeed-LLM，也不能只拿 100 题报告准确率。

用途数据为什么
速度测试从 test 固定随机抽取 100 题，seed=42所有 13 个配置使用同一批长短不一的真实 prompt；每题强制生成 128 token
正式性能测试完整 test，共 1319 题100 题波动太大，不能作为正式 GSM8K 分数
Few-shot 示例从 train 固定抽取 5 题，seed=42AR 与 12 个 Diffusion 配置共用完全相同的上下文

服务器路径按你提供的信息固定为：

lm-eval-harness: /home/f50058111/lm-eval-harness
HF 缓存根目录:   /home/f50058111/huggingface_cache
datasets 缓存:  /home/f50058111/huggingface_cache/datasets

prepare_gsm8k_data.py 会离线读取 openai/gsm8k 的 train/test cache，生成：

  • speed_prompts_100.jsonl：100 条固定测速 prompt，不包含标准答案。
  • fewshot_examples.json：固定的 5 个示例及训练集索引。
  • gsm8k_protocol.json：test/train 指纹、100 个 test 索引、seed 和 prompt SHA-256。
为什么保存指纹和索引：以后重跑时可以确认不是“同名数据集但换了版本或换了题”。

3. 已完成的代码改动

文件改动实验作用

summarize_block_step_results.py合并速度与正确率 JSON，生成 CSV 和 Markdown 汇总实验完成后直接抄表

本轮 Diffusion 的固定实现口径

  • seed_mode=none：每个 block 初始全部为 MASK，避免一个 AR seed 导致 B 个位置实际只去噪 B−1 个。
  • temperature=0、threshold=None：只比较 B/S，不引入额外采样变量。
  • 每个非最后 block 还有一次 KV refresh；所以实际 forward 数和理论 B/S 不相等，最终以 tok/s 为准。
  • 速度指标从 input IDs 已经在设备上开始计时，到生成结束；包含 prompt prefill，排除模型加载、tokenization 和 host-to-device copy。
  • 这是数据并行评测：每张 NPU 放一份完整模型，各自处理不同 prompt/题目；它提升整批实验吞吐，不会把单条请求拆到 8 张卡上。
  • decode_tokens_per_second 用所有样本设备耗时之和计算，是主表采用的单请求等价速度；aggregate_tokens_per_second 用最慢 rank 的墙钟时间计算，只表示 8 卡总处理能力。
与 lm-evaluation-harness 的关系：本地 lm_eval/tasks/gsm8k/gsm8k.yaml 定义的是 openai/gsm8k/main、5-shot、Question/Answer 模板、greedy（temperature=0）以及三个停止串；当前脚本复用了这些评测约定。由于 AR-Diffusion 必须调用仓库自己的 generate_once()，不能直接换成 lm-eval 的普通 Hugging Face 模型适配器。

4. 在服务器上怎么运行

cd /你的路径/MindSpeed-LLM

export MODEL_PATH=/data2/model_train/ckpt/phase4_cpt_ar_diffusion_0923_resume/models/global_step_102500
export LM_EVAL_ROOT=/home/f50058111/lm-eval-harness
export HF_CACHE_ROOT=/home/f50058111/huggingface_cache

若 step 102500 的导出目录名不同，只改 MODEL_PATH，不要改脚本。应指向包含 config.json 和模型权重的 Hugging Face 目录，不是分布式训练状态目录。

4.2 确认 Python

脚本优先使用 /home/f50058111/lm-eval-harness/.venv-diffusion/bin/python。先在当前终端显式保存这个变量；若文件不存在，再改成训练/推理环境的 Python：

export PYTHON_BIN=${PYTHON_BIN:-$LM_EVAL_ROOT/.venv-diffusion/bin/python}
# 若上面的文件不存在：export PYTHON_BIN=/实际环境/bin/python
$PYTHON_BIN -c "import torch, torch_npu, transformers, datasets; print('environment ok')"

4.3 第一步：抽取并冻结 100 条速度样本

PHASE=prepare bash examples/fsdp2/qwen3_diffusion/run_block_step_experiments.sh

看到 test_size: 1319、num_speed_prompts: 100 后，再检查：

wc -l "$OUTPUT_ROOT/data/speed_prompts_100.jsonl"
cat "$OUTPUT_ROOT/data/gsm8k_protocol.json"
如果这里失败，不要下载到仓库里：先确认 cache 中确实存在 GSM8K，以及运行 Python 的 datasets 版本能读取该缓存。脚本已开启 offline 模式，不会偷偷联网拿另一个版本。

4.4 第二步：先做一个 16 题、8 卡 smoke test

NUM_NPUS=8 PHASE=smoke bash examples/fsdp2/qwen3_diffusion/run_block_step_experiments.sh

请优先使用这一行，不要手工拼 torchrun 参数。启动脚本会在 Python 启动前设置 Hugging Face 离线变量，避免 8 个 rank 同时访问 huggingface.co。

16 题会让每张卡正好处理 2 题。先用 npu-smi info 确认 8 张卡均有显存和利用率，再检查合并后的 samples.jsonl。smoke test 分数不能填进正式实验表。

4.5 第三步：跑速度

NUM_NPUS=8 PHASE=speed bash examples/fsdp2/qwen3_diffusion/run_block_step_experiments.sh

执行顺序是 AR-BASE → 12 个 Diffusion 配置。每个配置的 100 条 prompt 按 index % 8 分给 8 张卡（每卡 12 或 13 条），每个 rank warmup 5 次，再重复 20 轮；全局仍是 2000 次正式生成，每次无视 EOS 并严格生成 128 token。

如某次中断，直接重新执行：已有 JSON 会跳过。确定要重跑并覆盖全部已有结果时才加 OVERWRITE=1。

4.6 第四步：跑完整 GSM8K

NUM_NPUS=8 PHASE=quality bash examples/fsdp2/qwen3_diffusion/run_block_step_experiments.sh

这一步运行 AR + 12 个配置 × 1319 题。每张卡处理约 165 题，每 10 个本地样本打印一次进度，并立即写入自己的 rank JSONL。中断后重跑会校验 run_protocol.json 并让各 rank 从自己的已有题数继续；全部结束后 rank 0 检查 0–1318 是否完整且无重复，再合并结果。

已有单卡残留结果时：单卡和 8 卡的断点文件协议不同，不能混续。请换一个新的 OUTPUT_ROOT；若确认旧结果不要了，才使用 OVERWRITE=1。

4.7 汇总结果

PHASE=summarize bash examples/fsdp2/qwen3_diffusion/run_block_step_experiments.sh

如果想从头到尾一次执行，可使用 PHASE=all；默认不写 PHASE 时只执行安全的 prepare 阶段，避免误启动长时间实验。

6. embedding 拷贝到 lm_head 到底对不对

你说的“用于初始化”是对的；问题只在于不能覆盖 checkpoint 中已经训练好的 head。

modeling_qwen3_diffusion.py 现在的逻辑是：

head_is_missing = any(key.endswith("lm_head.weight") for key in missing_keys)
if head_is_missing:
    model.lm_head.weight.copy_(model.model.embed_tokens.weight)
  • Base checkpoint 没有独立 lm_head.weight：复制 embedding 作为初始化，正确。
  • joint CPT checkpoint 已保存训练后的 lm_head.weight：直接保留，不再复制。

因此这不是一项需要 sweep 的实验，只是一次加载正确性修复。

7. 常见报错

找不到 GSM8K cache
确认 HF_CACHE_ROOT=/home/f50058111/huggingface_cache。如果日志反复出现 Failed to resolve huggingface.co，说明手工命令没有在 Hugging Face Hub 初始化前进入离线模式；先中止该进程，执行 4.1 中的五个 HF 环境变量，再重跑。新版评测脚本也会在导入 torch/transformers 前强制启用离线模式。如果实际只保存了 Arrow cache，目录下通常会有 datasets/openai___gsm8k 或类似名称。不要把 Windows 的 E:\... 路径传到服务器。
找不到 torch_npu
当前选择的是 lm-eval-harness 的 Python，但该环境没有继承服务器 NPU 包。把 PYTHON_BIN 指向训练/推理时使用的 Python，并确保里面同时有 torch_npu、transformers、datasets。
AssertionError: args is not initialized（报错位置是 dist.barrier()）
这不是 GSM8K cache 或 HCCL 初始化失败。日志若已经出现 8 个 rank 且显示 Using latest cached version，说明数据和多进程启动都正常；原因是 MindSpeed 把 torch.distributed.barrier/all_gather_object 包成了高可用版本，该包装层会读取尚未初始化的 Megatron args。新版 distributed_experiment.py 只在独立实验辅助类中调用包装层下面的原生 HCCL collective，不修改训练代码。同步新版文件后，直接重新执行 4.4 的 smoke 命令即可；上次失败发生在模型加载和逐题写入之前，只有旧 run_protocol.json 也可以安全重跑。若目录中已有旧版 samples.rank*.jsonl，使用新的 OUTPUT_ROOT，或确认不要旧结果后加 OVERWRITE=1。
还是只有一张 NPU 在工作
确认命令前有 NUM_NPUS=8，日志应同时出现 rank 0–7，速度 JSON 中 distributed_world_size 应为 8。若手工直接执行 python benchmark_decode.py，它就是单进程，只会使用一张卡；请使用本手册的 torchrun 命令或统一启动脚本。
8 卡启动后显存不足
数据并行会在每张卡各加载一份完整模型，因此要求单张 NPU 能放下模型。如果单卡本来就放不下，才需要 FSDP/张量并行；本轮 1.7B 模型优先使用更简单、结果也更容易解释的数据并行。
模型目录不存在
脚本默认推断为 .../models/global_step_102500。如果导出目录命名不同，只设置 MODEL_PATH；目录内应能看到 Hugging Face 的 config、tokenizer 和权重文件。
某个 block 仍包含 MASK
正式矩阵中 S≤B 且 threshold 关闭，理论上每步固定提交一部分 token，不应出现。若出现，保留报错和对应 B/S，不要把不完整输出计入结果。
parse_rate 很低
先查看 samples.jsonl。若模型给出了答案但格式没有被识别，应统一修改答案提取器并重跑 AR 和所有 Diffusion 配置，不能只为一个配置改规则。
